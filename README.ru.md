## Проблема: Раздражающий вирус `Gallery.exe`

Вы устали удалять вредоносное ПО `Gallery.exe` только для того, чтобы оно снова появлялось после перезагрузки? Этот распространенный вирус работает, размещая свой исполняемый файл в определенных пользовательских и системных папках. Даже после очистки вашей системы он часто возвращается, потому что исходный источник заражения (например, запланированная задача или другой скрытый процесс) пытается воссоздать его.

## Решение: Цифровая крепость

**Gallery-Lock** не просто удаляет вирус; он строит на его месте постоянную крепость. Скрипт создает файлы-приманки нулевого размера (пустые) с именем `Gallery.exe` в точных местах, на которые нацелено вредоносное ПО. Затем он применяет чрезвычайно строгие разрешения безопасности (ACL), которые делают эти приманки **невозможными для перезаписи или удаления вредоносным ПО**.

Результат? Попытка вредоносного ПО повторно заразить вашу систему блокируется на уровне операционной системы, каждый раз.

## 🛠️ Как использовать: 2-минутное руководство

Для максимальной эффективности скрипт должен выполняться от имени `SYSTEM`. Это самый высокий уровень полномочий в Windows, даже выше, чем у администратора.

### Рекомендуемый метод: запуск от имени SYSTEM с помощью PsExec

Это **самый безопасный метод**, который гарантирует, что скрипт сможет применить свои самые сильные средства защиты.

1.  **Скачайте PsExec:**
    *   Скачайте официальный **Sysinternals Suite** от Microsoft: [**Скачать здесь**](https://learn.microsoft.com/en-us/sysinternals/downloads/psexec).
    *   Извлеките ZIP-архив в простое место, например, `C:\Sysinternals`.

2.  **Откройте терминал от имени администратора:**
    *   Нажмите `Win + X` и выберите **Терминал (администратор)** или **Windows PowerShell (администратор)**.

3.  **Перейдите в папку PsExec:**
    *   В терминале перейдите в каталог, куда вы извлекли PsExec.
      ```powershell
      cd C:\Sysinternals
      ```

4.  **Запустите PowerShell на уровне SYSTEM:**
    *   Выполните следующую команду. Откроется новое окно PowerShell с привилегиями `SYSTEM`.
      ```powershell
      .\PsExec64.exe -i -s powershell.exe
      ```

5.  **Запустите скрипт Gallery-Lock:**
    *   В **новом окне SYSTEM** перейдите туда, где вы сохранили `Gallery-Lock.ps1`.
    *   Сначала установите политику выполнения для этого одного сеанса, а затем запустите скрипт.
      ```powershell
      # Разрешить запуск скрипта только в этом окне
      Set-ExecutionPolicy Bypass -Scope Process -Force

      # Запустить скрипт (используйте правильный путь)
      .\Gallery-Lock.ps1
      ```

**Вот и все!** Файлы-приманки теперь на месте и защищены. Вы можете закрыть все окна.

<details>

  > [!NOTE]
  > Этот метод работает, но защита файлов не так сильна, потому что администратор все еще может легче завладеть правами. Рекомендуется только в том случае, если вы не можете использовать PsExec.

  1. **Щелкните правой кнопкой мыши** по файлу скрипта `Gallery-Lock.ps1`.
  2. Выберите **"Запустить с помощью PowerShell"**.
  3. При появлении запроса подтвердите запрос UAC (Контроль учетных записей пользователей), чтобы предоставить ему права администратора.

  Скрипт уведомит вас, что он запущен от имени администратора, а не SYSTEM.

## 🗺️ Защищенные расположения файлов

Скрипт создает и защищает приманки в следующих стандартных путях вредоносных программ:

| Тип профиля | Путь |
| :--- | :--- |
| **Профиль пользователя** | `%APPDATA%\Gallery.exe` |
| **Системный профиль** | `C:\Windows\SysWOW64\config\systemprofile\AppData\Roaming\Gallery.exe` |

## 🧱 Как это работает: технический разбор

Эффективность скрипта основана на многоуровневой стратегии безопасности:

1.  **🔍 Сканирование и очистка:** Сначала он проверяет и удаляет все существующие файлы `Gallery.exe` в целевых местах, обеспечивая чистый старт.
2.  **📝 Создание приманки:** Создается пустой файл размером 0 байт с именем `Gallery.exe`. Он безвреден и не занимает места.
3.  **🛡️ Построение крепости (усиление ACL):** Это самый важный шаг. Скрипт изменяет список управления доступом (ACL) файла:
    *   **Блокирует наследование:** Он запрещает файлу наследовать разрешения от родительской папки. Это изолирует его от любых будущих изменений безопасности.
    *   **Запрещает всем:** Он добавляет явное правило `Deny FullControl` для группы `Все`. В Windows явное правило `Deny` всегда имеет приоритет над любыми правилами `Allow`. Это означает, что ни один пользователь, **даже администратор**, не может записывать, изменять или удалять файл.
    *   **Предоставляет контроль SYSTEM:** Он гарантирует, что только учетная запись `NT AUTHORITY\SYSTEM` или `TrustedInstaller` имеет `FullControl`. Это необходимо для целостности системы, но это учетная запись, которую вредоносное ПО (и пользователи) не могут легко использовать.
4.  **👻 Стать невидимым:** Наконец, он устанавливает атрибуты файла на `Скрытый` и `Системный`, скрывая его от стандартного просмотра в Проводнике, чтобы предотвратить случайное обнаружение или подделку.

## ⚠️ Важные предупреждения и как отменить

> [!WARNING]
> **Этот скрипт создает файл, который *намеренно* трудно удалить, даже для вас.** Не запускайте это на любом файле, к которому вам может понадобиться доступ позже. Он разработан специально для блокировки известных путей вредоносных программ.

### Как вручную удалить заблокированный файл-приманку

Если вам когда-нибудь понадобится удалить приманки, вы должны вручную отменить защиту как **администратор**.

1.  **Откройте терминал от имени администратора** (`Win + X` > Терминал (администратор)).
2.  **Завладейте** файлом. Замените путь на правильный.
    *Для файла пользователя:*
    ```cmd
    takeown /f "%APPDATA%\Gallery.exe"
    ```
    *Для системного файла:*
    ```cmd
    takeown /f "C:\Windows\SysWOW64\config\systemprofile\AppData\Roaming\Gallery.exe"
    ```
3.  **Сбросьте разрешения**, чтобы они наследовались от родительской папки.
    *Для файла пользователя:*
    ```cmd
    icacls "%APPDATA%\Gallery.exe" /reset
    ```
    *Для системного файла:*
    ```cmd
    icacls "C:\Windows\SysWOW64\config\systemprofile\AppData\Roaming\Gallery.exe" /reset
    ```
4.  Теперь вы можете **удалить файл** как обычно.
    ```powershell
    Remove-Item -Path "$env:APPDATA\Gallery.exe" -Force
    ```

## 🔎 Устранение неполадок и часто задаваемые вопросы

| Симптом / Вопрос | Решение / Объяснение |
| :--- | :--- |
| ❌ **Ошибка "Доступ запрещен" во время выполнения скрипта.** | Это ожидаемо, если вы запускаете его от имени администратора, а не SYSTEM. Скрипт не может установить `SYSTEM` в качестве владельца. **Используйте метод PsExec для полной защиты.** |
| 📜 **Ошибка "Выполнение скриптов отключено в этой системе".** | Это ошибка политики выполнения PowerShell. Вы можете обойти ее для текущего процесса, выполнив `Set-ExecutionPolicy Bypass -Scope Process -Force` перед запуском основного скрипта. |
| 🪟 **Я не вижу файл `Gallery.exe` в Проводнике.** | Это сделано намеренно. Файл скрыт. Чтобы просмотреть его, перейдите в Проводник > `Вид` > `Параметры` > вкладка `Вид` и установите флажок **"Показывать скрытые файлы..."** и снимите флажок **"Скрывать защищенные системные файлы"**. |
| 🗑️ **Я не могу удалить файл, даже будучи администратором!** | Это означает, что скрипт работает правильно! Он предназначен для блокировки всех, включая вас. Следуйте инструкциям в разделе **[Как отменить](#️-важные-предупреждения-и-как-отменить)**, чтобы удалить его. |
| 🤔 **Почему так важно запускать от имени `SYSTEM`?** | Учетная запись `SYSTEM` является высшим авторитетом в Windows. Делая `SYSTEM` владельцем приманки, это не позволяет даже администратору легко изменять ее без предварительного явного завладения. Вредоносное ПО, работающее с правами администратора, будет заблокировано, что является огромным преимуществом в безопасности. |
